# Souq Al-Hay API

باك إند تطبيق "سوق الحي" — NestJS + Prisma + PostgreSQL + Docker.

## ✅ جاهز حالياً

### 1. Authentication
- تسجيل برقم الهاتف عبر OTP (رمز 6 أرقام، صلاحية 5 دقائق، hashed بـ bcrypt)
- JWT Access Token (15 دقيقة) + Refresh Token (30 يوم) مع **تدوير كامل** (rotation) عند كل تحديث
- تسجيل خروج يُبطل الـ Refresh Token المحدد

### 2. إدارة الإعلانات
- CRUD كامل (إنشاء، تعديل، حذف، تعليم كمباع)
- رفع صور متعددة لكل إعلان (تخزين محلي حالياً، راجع `multer.config.ts`)
- أي إعلان جديد أو معدّل يرجع لحالة `PENDING` لحد ما الأدمن يوافق عليه

### 3. البحث والأقسام
- فلترة حسب القسم، المنطقة، نطاق السعر، نص حر بالعنوان
- ترتيب: الأحدث / السعر تصاعدي / تنازلي (والإعلانات المُرقّاة تظهر بالأعلى دائماً)
- صفحات (pagination)
- `GET /api/categories` و`GET /api/areas` لقوائم الفلاتر

### 4. المحادثات (Socket.IO + REST)
- REST: بدء محادثة، عرض المحادثات، عرض الرسائل (يُعلّمها كمقروءة تلقائياً)
- Socket.IO (namespace `/chat`): `joinConversation`, `sendMessage`, `markRead`، مصادقة عبر JWT بالـ handshake

### 5. المحفظة والمدفوعات (شام كاش)
- شحن رصيد (طلب + تأكيد) — ⚠️ التأكيد حالياً "محاكاة" للتطوير فقط، راجع التعليق بـ `wallet.service.ts`
- ترقية إعلان (خصم من الرصيد + تحديد `boostedUntil`)
- سجل العمليات الكامل لكل مستخدم

### 6. الإشعارات والإدارة
- إشعارات داخل التطبيق (تُنشأ تلقائياً عند: اعتماد/رفض إعلان، رسالة جديدة)
- تسجيل أجهزة FCM (الإرسال الفعلي عبر Firebase لسا TODO، راجع `notifications.service.ts`)
- البلاغات: تقديم + مراجعة الأدمن
- لوحة تحكم أدمن بسيطة: `/api/admin/stats`، `/api/listings/admin/pending`، `/api/reports`

### 💳 نظام تسعير الإعلانات (جديد)
- **أول 3 إعلانات مجانية** لكل مستخدم (`FREE_LISTINGS_COUNT` بملف `.env`)
- بعدها: إما **باقة فعّالة** (5/20/50 إعلان، أسعار افتراضية بالـ seed - عدّلها من جدول `Package`)
  أو **دفع لكل إعلان لحاله** (`LISTING_PRICE_SYP`، افتراضياً 10 ل.س جديدة)
- الدفع **يدوي بالكامل عبر شام كاش** (ما في API رسمية): النظام بيعرض للمستخدم رقم/QR الاستلام
  (`GET /api/payments/settings`)، المستخدم بيحوّل من تطبيقه هو، وبعدين الأدمن بيتأكد يدوياً من
  داخل تطبيق شام كاش عنده إنه المبلغ وصل، وبيأكد الطلب من `/api/payments/admin/:id/confirm`
- لحد ما الأدمن يأكد الدفع، الإعلان بحالة `AWAITING_PAYMENT` (مش ظاهر لحدا). بعد التأكيد بيصير
  `PENDING` (يدخل نفس طابور مراجعة المحتوى العادي)
- إدارة إعدادات الاستلام: `PATCH /api/payments/admin/settings` (رقم شام كاش + الاسم)
  و `POST /api/payments/admin/settings/qr-image` (رفع صورة QR)

### 📢 إشعار بث عام عند نشر إعلان جديد (جديد)
لما الأدمن يوافق على إعلان (`/api/listings/admin/:id/approve`)، النظام بيبعت إشعار Push **لكل
المستخدمين** (عبر FCM topic، افتراضياً `new_listings`) بصيغة: "تم نشر إعلان عن {العنوان} بمنطقة
{الحي}، {المدينة}". كل جهاز بيشترك بالـ topic تلقائياً لما يسجّل الـ device token
(`POST /api/notifications/device-token`).

⚠️ **بدون ربط Firebase فعلياً** (راجع قسم Firebase تحت)، هاد البث بيتسجّل باللوج بس وما بينبعث
Push حقيقي - التطبيق بيشتغل عادي بدونه، بس المستخدمين ما رح يوصلهم إشعار فعلي.

#### ربط Firebase (اختياري لحد ما تحتاجه فعلياً)
1. بكونسول Firebase: مشروعك ← Project Settings ← Service Accounts ← Generate new private key
2. من ملف الـ JSON اللي بينزّل، انسخ 3 قيم فقط لملف `.env` عندك (لا تشارك الملف نفسه مع أي أحد):
   - `FIREBASE_PROJECT_ID`
   - `FIREBASE_CLIENT_EMAIL`
   - `FIREBASE_PRIVATE_KEY` (خليها بين علامتي اقتباس زي المثال بـ `.env.example`)

## 🌱 بيانات وهمية للتجربة (Seed)
```bash
npm run db:seed
```
هاد بيعبّي القاعدة بـ: 6 أقسام، 6 مناطق بدمشق، 6 مستخدمين (أولهم أدمن برقم `+963900000001`)،
3 باقات إعلانات، إعدادات شام كاش جاهزة، 11 إعلان (معظمها نشطة، اثنين PENDING لتجربة موافقة
المحتوى، **وواحد AWAITING_PAYMENT لتجربة طابور مراجعة المدفوعات بالأدمن**، واحد مُرقّى، وواحد مباع)،
محادثة فيها 4 رسائل (آخر وحدة غير مقروءة)، عمليتي محفظة، عمليتي دفع (وحدة معلّقة ووحدة مؤكدة
لباقة)، إشعارين، وبلاغ واحد.

**مستخدمين جاهزين لتجربة كل حالات نظام التسعير:**
- خالد (`+963912345678`): استخدم إعلان مجاني وحد، لسا عنده 2
- أبو محمد (`+963933111222`): استخدم 2، لسا عنده 1 مجاني
- سارة (`+963944222333`): استهلكت المجاني بالكامل، بس عندها باقة فعّالة (5 إعلانات)
- رامي (`+963955333444`): ما استخدم ولا إعلان بعد (3 مجانية كاملة)
- لينا (`+963966444555`): استهلكت المجاني وما عندها باقة - أي إعلان جديد رح يطلبلها دفع فوراً

⚠️ يمسح كل البيانات الموجودة قبل ما يعبّي من جديد - لا تشغّله على قاعدة إنتاج حقيقية.

## التشغيل محلياً

```bash
# 1) تشغيل قاعدة البيانات
docker compose up -d

# 2) تثبيت الحزم (إذا لسا ما عملتها)
npm install

# 3) توليد Prisma Client وتطبيق أول migration
npx prisma generate
npx prisma migrate dev --name init

# 4) تعبئة بيانات وهمية للتجربة (اختياري لكن مستحسن)
npm run db:seed

# 5) تشغيل السيرفر
npm run start:dev
```

السيرفر رح يشتغل على `http://localhost:3000/api`

## اختبار سريع لمسار تسجيل الدخول (Auth)

```bash
# 1) طلب رمز تحقق (بالتطوير، الرد بيرجع الكود نفسه بحقل devCode لتسهيل الاختبار)
curl -X POST http://localhost:3000/api/auth/otp/request \
  -H "Content-Type: application/json" \
  -d '{"phone": "+963912345678"}'

# 2) التحقق من الرمز (استخدم القيمة اللي رجعت بـ devCode)
curl -X POST http://localhost:3000/api/auth/otp/verify \
  -H "Content-Type: application/json" \
  -d '{"phone": "+963912345678", "code": "123456"}'

# الرد بيرجع accessToken + refreshToken + userId
```
